# CHZZK API·타임스탬프 조사 (2026-11-02)

현재 코드, 사용자가 제공한 실제 응답, 공개 구현을 비교했습니다. 아래 service/polling 경로와 채팅 프로토콜은 공식 개발자 API의 안정성 보장이 확인된 계약이 아닌 웹 서비스 내부 구현입니다. 로그인한 실서비스에서의 최종 검증은 별도로 필요합니다.

| 이전 목표 | 확인한 근거 | 활용 범위·남은 점 |
| --- | --- | --- |
| 채팅 헤더 통나무 잔액 | 사용자 확인 GET `/service/v1/channels/{channelId}/log-power`, `content.amount` | 현재 채팅 채널을 30초 간격 조회하도록 연결. channelId·active·정수 amount 검증. 실패하면 프로필/마지막 확인 값/— 표시. |

| 통나무 보너스 수령 | 잔액 응답 `claims: []` | 비어 있는 배열로 수령 API·조건·본문을 알 수 없음. 보너스가 있는 상태의 조회 응답과 원본 받기 동작의 URL/메서드/응답이 필요. 현재 구현은 네이티브 버튼 보조 수준이며 전체 채널 수령 보장 없음. |

| 팔로잉 목록 | 현재 사용 중 `/service/v1/channels/followings` | 이미 API 사용 중. 별도 새 API를 찾는 것보다 페이지 처리·로그인 실패 처리 유지가 우선. |
| 녹화 끊김·빠른 구간 저장 | 이번 조사 자료에서 관련 서버 API 확인 못 함 | 로컬 캡처·인코딩·컨테이너 편집 문제로 따로 다뤄야 함. API 하나로 해결된다고 볼 근거 없음. |

## 참고 타임스탬프 확장 비교

[huntmori/chzzk-timestamp](https://github.com/huntmori/chzzk-timestamp/tree/0bd7356d2c80d3df18a2d1f18720f56613ce60e3)의 `src/injector/injector.js`와 `src/content/content.js`를 읽었습니다.

- document_start의 MAIN 월드에서 기존 WebSocket을 관찰하고 실시간 배열, 최근 메시지 messageList, 문자열 bdy를 해석합니다. messageTime/createTime을 사용합니다.
- DOM에서는 닉네임별 FIFO 큐로 시간을 소비합니다. 원본 시각을 찾지 못하면 현재 시각을 표시하고, 500ms마다 전체 후보를 재검사합니다.
- 현재 프로젝트는 이미 기존 소켓 관찰과 원본 시각 색인을 갖추고 있습니다. 문자열 bdy와 createTime을 지원합니다. 11월 2일 재확인한 참고 저장소의 main도 위 커밋과 같습니다. 추가로 설정 ON인 채팅 URL에 초기 수신 허용 플래그를 전달해 늦은 설정 메시지 이전의 최근 기록을 놓치지 않도록 했습니다. 이름+내용과 가능한 메시지 ID로 대조하며, 서로 다른 시각의 같은 내용은 ID 없이 추측하지 않습니다.
- `extras.emojis`의 이모티콘 토큰과 원본 이미지 경로를 대조하고, React children 배열도 제한된 범위에서 읽습니다. 같은 작성자의 메시지 ID가 일치하면 이미지 표현 차이와 무관하게 원본 시각을 사용합니다. DOM이 먼저 생긴 경우 소켓 수신 뒤 해당 행만 다시 검사합니다. 대기 색인은 최대 128개 키·키별 8개 약한 참조이며 OFF/종료 시 정리합니다.
- 스크롤 재마운트에도 같은 원본 시각을 재사용합니다. 현재 시각 대체·닉네임 FIFO·500ms 전체 재검사는 도입하지 않습니다. 타임스탬프 기본 OFF, 색인 최대 2,048개, OFF/종료 시 정리는 유지합니다.
- 참고 저장소에서 재사용 허가를 명시한 LICENSE를 찾지 못해 소스 코드를 복사하거나 의존성으로 포함하지 않았습니다.

추가 비교: [kimcore/chzzk](https://github.com/kimcore/chzzk/tree/9208ad6901242c2854c44d6b13e219d7d023239d)의 `src/chat/chat.ts`는 최근/실시간 메시지와 msgTime/messageTime 처리를 보여 줍니다. 이 자료에서 통나무 수령 API는 확인하지 못했습니다.

로그인 쿠키·토큰을 내보내거나 저장할 필요는 없습니다. 추가 점검 자료는 인증 헤더를 제외한 URL·메서드·필요한 응답 필드만으로 충분합니다.

## Badge Moa Chat 추가 비교 (2026-11-02)

사용자가 지정한 [badge-popup.js](https://github.com/lirpa62/Chzzk-Badge-Moa-Chat/blob/a3bb01a59f2d88a147d6a9dbe67143985a896533/badge-popup/main/badge-popup.js)는 조립용 진입점입니다. 실제 원본 채팅의 작성 시각 판독은 같은 커밋의 `inject.js` 내 `getChatMessage`, `readChatEpochMs`에서 처리합니다.

- 행의 React props뿐 아니라 하위 Fiber의 `memoizedProps.chatMessage`에서도 시각을 읽습니다. 이 프로젝트도 행의 자식 체인 최대 32개를 확인하도록 독립적으로 보완했습니다. 형제 행은 탐색하지 않고 기존 작성자·본문/ID 검증과 전체 탐색 예산을 유지합니다.
- 기존 시각 필드에 `time`, `regTime`, `timestamp`를 추가했습니다. 이 세 일반 필드는 epoch 밀리초인 값만 허용하며, `playerMessageTime`이나 상대 경과 시간은 배제합니다. 잘못된 우선 필드가 있어도 나머지 유효 필드를 확인합니다.
- React 데이터가 DOM 삽입보다 늦게 붙는 상황에 대비해 행별 최대 4회만 재시도합니다. 대기 타이머는 최대 128개이며 OFF·종료 시 해제합니다. 현재 시각 대체나 상시 전체 검색은 추가하지 않습니다.
- 참조 구현은 원본 채팅의 epoch 판독과 모아보기의 수집 시각 대체가 다른 경로에 존재합니다. 모아보기의 `Date.now()` 대체를 가져오지 않고 실제 작성 시각만 표시하는 기존 원칙을 유지합니다. 소스 코드는 복사하거나 포함하지 않았습니다.

## Badge Moa 방향의 원본 시각 우선 판독 (2026-11-02)

이전 비교에서 원본 시각이 있어도 프로필·문자열 본문 검증으로 버리는 조건을 모의 재현했습니다. 명시적인 행 소유 `chatMessage` / `chattingMessage`는 원본 epoch만 우선 판독하도록 독립 구현했습니다. 표시된 이름·본문과의 대조는 소유 관계가 확인되지 않는 상위 데이터/소켓 보조 경로에만 적용합니다. 후보 충돌과 다른 행은 배제하고, ID별 원본 시각을 제한된 색인에 유지합니다. 참조 코드를 복사하거나 현재 시각 대체 방식을 도입하지 않았습니다.
