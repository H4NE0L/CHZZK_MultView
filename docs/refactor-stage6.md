# 리팩토링 6단계 — 최종 구조·배포 정리

계획한 마지막 구현 단계입니다. 1~5단계는 사용자 테스트를 마쳤으며 6단계는 테스트 브랜치 `refactor/runtime-foundation`에 제공합니다. 버전은 **2.0.3**으로 유지하고 main에는 반영하지 않습니다.

## 변경 내용

- 플레이어·음량·채팅·싱크·미디어·레이아웃 등 멀티뷰 내부 모듈을 ES import로 연결합니다. 테스트에서만 필요했던 `CZ*` 전역 연결은 제거합니다. 콘텐츠 스크립트와 독립 실행 화면의 저장소·메시지 등 실제로 사용하는 공용 연결은 유지합니다.
- CSS를 기본 화면·목록·즐겨찾기·타일·채팅 등으로 나눕니다. `config/styles.json` 순서대로 합쳐 기존 배포 경로에 생성하므로 Shadow DOM과 페이지 모드에서 같은 스타일을 사용합니다. 기존 cascade를 유지하며 확인된 미사용 `.tile-refresh:hover`만 제거합니다.
- HTML·manifest·runtime 목록·동적 진입점·정적 importScripts 의존성만 dist에 생성합니다. import한 내부 모듈은 진입점에 묶습니다. 녹화 변환 라이브러리는 기존처럼 Worker에서 지연 로드합니다.
- 단위 검사 모듈은 `.test-build`에 따로 생성합니다. 테스트용 별칭과 export는 배포하지 않습니다. vendor 파일과 라이선스는 그대로 유지합니다.
- `npm run verify`는 한 번 빌드한 결과에 타입·단위·브라우저·백업·미디어·채팅 검사를 순차 적용합니다. Node.js 24 권장이며 Chromium 경로는 `CHROMIUM_PATH`로 지정할 수 있습니다.

전체 TypeScript 전환, UI 재설계, 음량·채팅 알고리즘 변경은 이번 정리에 포함하지 않습니다. 즐겨찾기·그룹·설정·세션 저장 키와 iframe 유지 규칙을 보존합니다.

## 검증 범위

타입 검사와 단위 검사 116개, 전용 페이지·홈페이지 모드의 모의 CHZZK 브라우저 검사, 백업/복원, 채팅 DOM fixture·원본 작성 시각 판별·반복 생성/해제, 실제 생성 영상의 캡처·녹화·MP4/WebM 구간 저장 검사를 수행합니다. 패키지 검사는 HTML/manifest/importScripts 참조, 테스트 export 미포함, CSS 합성 순서와 기존 경로를 확인합니다.

반복 해제 검사는 수집기와 채팅 패널을 각각 30회 생성·종료하여 감시자·타이머·이벤트·저장소 구독이 남지 않는지 확인합니다. 이는 실제 CHZZK 장시간 시청이나 브라우저 전체 메모리 감소율을 증명하지 않습니다. 로그인·DNR·외부 확장 호환과 실방송 재생은 사용자 Chrome에서 확인해야 합니다.

## 최종 직접 확인

기존 설치를 삭제하거나 새 경로에 등록하지 말고 먼저 설정을 백업합니다. 같은 프로젝트 경로에서 테스트 브랜치를 받아 `npm ci`와 `npm run build` 후 기존 dist 확장을 다시 로드합니다. 열린 멀티뷰도 다시 여세요.

1. 전용 새 탭·새 창과 치지직 페이지 모드에서 즐겨찾기·팔로잉·그룹·설정이 유지되는지 확인합니다.
2. 타일 추가/제거·순서/배치 변경 후 남은 플레이어와 개별 음량이 유지되는지 확인합니다.
3. 원본 채팅 메뉴·모아보기·수집 설정·중복 억제와 헤더 배치를 확인합니다. 원본 작성 시각이 없는 채팅에는 시간을 만들지 않는 기존 규칙을 유지합니다.
4. 스크린샷 자르기·복사·저장·목록 이동과 녹화 시작/종료·음성·구간 저장을 확인합니다.
5. 동일 화질로 30분 이상 시청하며 Chrome 작업 관리자의 메모리·CPU와 버퍼링을 관찰합니다. 타일/채팅/갤러리를 반복해서 열고 닫은 결과도 기록합니다. 정량 비교에는 동일 환경의 이전 단계 측정이 필요합니다.

전체 설계의 여섯 구현 단계는 여기서 마무리합니다. 실제 Chrome 최종 테스트와 이후 전달되는 수정·문제사항은 별도로 처리하며, 검증 전 릴리스 완료나 성능 개선 수치를 선언하지 않습니다.
