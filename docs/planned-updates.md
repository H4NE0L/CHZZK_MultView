# 다음 업데이트 검토 항목

## 멀티뷰 시청 방송의 통나무 획득

- 등록일: 2026-10-29
- 상태: 검토 예정, v2.0.3 미구현
- 목표: 메인 방송뿐 아니라 실제 시청 중인 모든 타일 방송에서 획득 가능한 통나무를 놓치지 않도록 합니다.
- 사용자 관찰: 현재는 하나의 메인 방송에서만 획득되는 것으로 보입니다. 원인은 아직 확인하지 않았습니다.

확인할 내용:

1. 자동 적립과 추가 획득 버튼 중 어떤 경로에서 누락되는지 구분합니다.
2. 같은 계정으로 일반 치지직 탭 여러 개를 시청할 때의 획득 동작을 기준으로 확인합니다.
3. 멀티뷰 타일의 로그인·재생·시청 상태 처리, 메인 선택과 채팅 프레임 연결이 획득에 영향을 주는지 비교합니다.
4. 치지직에서 여러 방송의 동시 획득을 지원하는지 확인합니다. 서버 제한 여부를 확인하기 전에는 구현 가능하다고 가정하지 않습니다.
5. 지원되는 경우 채널별 획득 상태를 표시하고, 필요한 획득 동작을 중복 없이 처리하는 방식을 설계합니다. 방송 제거·종료·로그아웃 때 해당 처리를 중지하도록 합니다.

구현 범위와 버전은 위 확인을 마친 뒤 결정합니다.

## 리팩토링과 TypeScript 점진 도입 검토

목표는 기능이 많아진 확장을 관리하기 쉬운 구조로 나누고 실행 비용을 줄이는 것입니다. TypeScript 자체는 컴파일 후 JavaScript로 실행되므로 CPU·메모리·패키지 크기를 자동으로 줄이지 않습니다.

1. 타일·원본 채팅·수집·녹화·저장 변환을 나눠 실제 CPU/GPU·메모리와 장시간 증가 여부를 측정합니다.
2. 반복 DOM 탐색·불필요한 타이머·메시지·화면 갱신을 줄이고, 무거운 처리는 필요할 때 로드하며 Worker로 분리합니다.
3. UI, 데이터 저장, 메시지 규약, 플레이어 제어의 경계를 정리합니다. 새 기능과 전체 언어 전환을 동시에 진행하지 않습니다.
4. 공용 데이터 모델·저장소·메시지부터 타입을 정의합니다. 기존 JS의 JSDoc/checkJs를 먼저 적용하거나 작은 TS 모듈부터 빌드에 포함하는 방식을 비교합니다.
5. 기능별 회귀 테스트를 통과한 모듈부터 순차 전환합니다. 런타임 메시지·저장 데이터 검증은 타입 도입 후에도 유지합니다.

현재는 검토 계획이며 전체 TypeScript 전환이나 빌드 도구 도입을 시작한 상태는 아닙니다.
