# 통나무 수집 보조와 점검

v3.0.1의 **설정 → 통나무 수집 보조 (실험)**는 기본 OFF입니다. 켜면 실제 열린 라이브 타일마다 극장 모드 자동 진입을 중단하고 원본 채팅 구성요소를 유지합니다. 플레이어는 CSS로 타일을 채우며 새 채팅 iframe이나 독립 적립 연결을 만들지 않습니다. 기존 사이트 설정에 따라 구성요소가 없거나 버튼을 찾지 못할 수 있습니다.

재생 중인 라이브 타일에서 ‘통나무’와 수령 동작이 명시된 원본 버튼만 5초 간격으로 확인합니다. 원본 버튼의 click 처리를 사용하고 확인되지 않은 적립/수령 API는 호출하지 않습니다. 승부예측·베팅·구매·사용·후원·채팅 본문 안의 버튼은 제외합니다. 같은 버튼/보너스를 연속 클릭하지 않으며, 종료·중지된 영상은 수령을 시도하지 않습니다. 기능 OFF·타일 종료 시 타이머와 스타일을 해제합니다.

원본 채팅 유지로 CPU·메모리 사용이 늘 수 있습니다. 이 기능은 자동 적립·보너스 지급을 보장하지 않습니다. 로그인 여부, 서비스의 다중 시청 조건, 원본 버튼의 실제 접근성과 클릭 허용 여부를 사용자 Chrome에서 확인해야 합니다.

## 점검

**전체 설정 → 통나무 파워 점검 → 점검 정보 복사**에서 재생·원본 구성요소·버튼·수령 보조의 클릭 시도 횟수와 최근 요청 경로를 읽습니다. 클릭 시도 횟수는 지급 성공 횟수가 아닙니다. 점검 버튼 자체는 원본 버튼을 누르거나 적립 요청을 보내지 않습니다.

사용자 v2.0.3 자료에는 메인 외 타일에도 `polling/v1/watch-event/live` 응답 204가 있지만 `chatMounted:false`, 버튼 없음이 관측됐습니다. 이전 선택자가 새 CSS 모듈 이름을 놓칠 수도 있어 실제 컴포넌트 제거로 단정하지 않습니다. v3에서는 chatting 계열도 검사합니다. 이는 지급 증거가 아니며 극장 모드와 원본 구성요소 유지가 영향을 주는지 비교하는 근거입니다.

같은 계정·방송에서 일반 탭 / 보조 OFF / 보조 ON을 비교하고 실제 통나무 수치와 보너스 지급을 기록하세요. 아직 실제 로그인 계정에서 지급 성공을 검증하지 못했습니다. 자동 검사는 원본 DOM 유지·명확한 버튼 선택·중복 방지·종료 시 해제를 검증합니다.

점검에는 쿠키·인증 헤더·쿼리값·응답 본문을 포함하지 않습니다. 리소스 이력은 최근 최대 300개 중 경로 최대 70개로 제한하며 긴 ID 경로는 마스킹합니다. 모달을 닫으면 자료와 타이머를 해제합니다.

## 채팅 헤더 잔액 표시

사용자가 원본 프로필에서 확인한 `GET https://api.chzzk.naver.com/service/v1/channels/{channelId}/log-power`를 사용합니다. 로그인 쿠키는 브라우저의 credentials:include로 전송하며 별도 키·토큰 저장은 하지 않습니다. code=200, content.channelId 일치, active=true와 0 이상의 정수 amount를 검증한 후 표시합니다. claims·랭킹 설정은 변경하지 않습니다.

현재 채팅 채널만 시작 시와 이후 요청 완료 30초 뒤에 조회합니다. 요청 제한 시간은 15초이며 채팅 종료 시 진행 요청과 타이머를 취소합니다. 다시보기에는 요청하지 않습니다. 실패·비활성·응답 불일치를 0으로 표시하지 않고 마지막 확인 값 또는 —로 표시합니다. 정상 API 값이 원본 프로필 DOM보다 우선합니다.

API를 읽지 못하면 원본 프로필의 ‘내 통나무 파워 300’ 표시를 보조로 읽습니다. 채팅 본문·보너스·승부예측 숫자는 제외합니다. 자동 프로필 클릭이나 적립·수령 API 요청은 하지 않습니다. 실제 계정에서 인증·잔액 반영은 사용자 확인이 필요하며 모의 API로 검증합니다.

음량 충돌 테스트 브랜치에서는 복사 결과의 `tabAudio`가 브라우저 탭 음소거 상태, 채널별 `audio`가 요청/실제 음량과 복구·보고 횟수를 담습니다. `earlyCapture:true`이면 document_start 음량 격리가 연결된 상태입니다. 인증 정보·저장소 값·채팅 내용은 포함하지 않습니다.
