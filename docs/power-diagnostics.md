# 통나무 파워 조사 — 2026-10-29

## 확인한 사실

- 현재 확장은 적립·수령 API를 직접 호출하지 않습니다. 방송 타일은 원본 치지직 페이지이고 채팅은 CSS로 숨깁니다. 극장 모드 전환도 요청하므로 원본 컴포넌트의 실제 유지 여부를 사용자 환경에서 확인해야 합니다.
- 별도 채팅 iframe은 선택된 방송 하나에 연결됩니다. 이것이 적립 원인이라는 증거는 아직 없습니다.
- 사용자는 일반 치지직 탭 두 개에서 시간별 자동 적립은 되지만 보너스 수령은 안 되는 것 같다고 설명했습니다. 자동 적립과 보너스는 구분해 점검합니다.
- 공개 참고 저장소 Cheese-PIP와 kimcore/chzzk에서 해당 구현을 찾지 못했습니다. 공개 치지직 HTML은 확인했지만 실제 JS가 위치한 ssl.pstatic.net은 이 실행 환경에서 proxy CONNECT 403으로 차단됐습니다. 확인되지 않은 API나 서버 제한을 추정해 구현하지 않습니다.

## 현재 제공한 기능

**전체 설정 → 통나무 파워 점검 → 점검 정보 복사**

실제로 열린 각 라이브 타일에 요청해 재생 상태, 문서 활성 상태, 원본 채팅 DOM 유지 여부, 통나무 관련 버튼 레이블, 최근 fetch/XHR/beacon의 리소스 경로를 읽습니다. 원본 버튼 클릭·적립/수령 요청·가시성/포커스 변경·추가 채팅 연결은 하지 않습니다. 자동 적립·자동 수령은 미구현입니다.

쿠키·인증 헤더·쿼리값·응답 본문은 읽지 않습니다. 긴 ID 경로는 마스킹합니다. 리소스 히스토리는 최근 최대 300개 중 경로 최대 70개를 반환하며, 브라우저 버퍼나 CORS에 따라 요청 이력·상태 코드가 없을 수 있습니다. 요청 방법·본문·응답으로 성공을 판정하는 기능이 아닙니다. 모달을 닫으면 응답 자료와 타이머를 해제하고 상시 관찰자를 두지 않습니다.

## 다음 확인

1. 같은 계정·같은 방송 두 개를 일반 탭과 멀티뷰에서 비교합니다. 로그인·실제 재생 여부와 통나무 증가를 확인합니다.
2. 멀티뷰를 몇 분 사용한 뒤 점검 정보를 복사합니다. 보너스 UI가 뜬 상태의 버튼 정보가 특히 필요합니다.
3. 채널별 적립 경로와 기본 채팅 컴포넌트 유지 상태를 비교해 클라이언트에서 누락되는 처리인지 확인합니다.
4. 보너스는 버튼이 없는 것인지, 직접 눌러도 다른 채널에서 거부되는 것인지 구분합니다.
5. 정상 동시 적립이 가능한 경로가 확인되면 원본 시청 처리의 유지와 정확한 보너스 버튼 자동 수령을 별도로 구현합니다. 로그인 해제·방송 종료·타일 제거 시 중단하고 중복 요청을 막습니다.

현재 단위/브라우저 검사는 읽기 전용·프레임 검증·비밀값 제외·여러 타일 UI만 확인합니다. 실제 적립이나 보너스 수령 성공을 검증한 상태가 아닙니다.
