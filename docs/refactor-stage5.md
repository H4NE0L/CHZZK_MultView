# 리팩토링 5단계 — 미디어 수명과 보관 한도

사용자 테스트를 마친 4단계 `1a56cb6`을 기준으로 진행합니다. 버전은 2.0.3이며 main 반영은 별도입니다.

## 자원 소유와 해제

| 자원 | 소유 모듈 | 해제 시점 |
| --- | --- | --- |
| 스크린샷 임시 canvas | content/media-frame.js, viewer/screenshot-crop.js | PNG 생성 완료/오류 후 크기를 0으로 초기화 |
| 저부하 녹화 canvas·자체 영상 트랙 | content/media-frame.js | 정상 중지·초기화 실패·프레임 종료 |

| 이름 조회 요청·응답 타이머·키 이벤트·녹화 표시 주기 | media-tools.js | 요청 완료/실패·타일 제거·전체 종료 |
| 재생 위치 캐시·대기 요청 | media-tools.js | 타일 제거·전체 종료 |

`shared/media/object-urls.ts`는 자신이 만든 URL만 관리합니다. `ResourceScope`와 함께 중복 해제는 무시하고 완료된 타이머 등록을 제거합니다. 원본 플레이어의 URL이나 captureStream 영상·음성 트랙은 정리 대상으로 삼지 않습니다. 직접 만든 녹화 canvas 트랙만 중지합니다.

## 동작과 보관 한도

`shared/media/limits.ts`에 보관 한도를 모았습니다.

- 스크린샷 처리 중 요청은 최대 2개입니다.
- 대기/미리보기 스크린샷은 최대 12장·128MB입니다. 한도에 도달하면 안내하고 기존 이미지는 유지합니다. 먼저 저장한 뒤 다시 촬영할 수 있습니다.
- 녹화는 기존 방송당 256MB 자동 중지 기준을 유지합니다. 마지막 인코딩 조각이 추가될 수 있어 홈페이지 전송에는 16MB 여유를 둔 272MB 안전 상한을 적용합니다.
- 홈페이지 전송은 탭별 한 건이며, 2분 동안 새 조각을 받지 못하면 정리합니다. 서비스 워커가 먼저 종료되면 메모리의 부분 전송도 사라집니다.
- 다운로드 URL 보유 시간은 기존 60초에서 10초로 줄였습니다. 화면 종료 시 즉시 해제합니다.

한도는 앱이 보관하는 Blob/대기 작업에 대한 것으로, 영상 디코딩·브라우저 캐시·운영체제 전체 메모리의 상한은 아닙니다. 여러 방송 녹화와 여러 결과 창의 동시 변환은 여전히 많은 메모리를 사용할 수 있습니다.

## 녹화 보호와 전송

녹화 중인 방송이 화면 밖으로 밀려 프레임이 제거되는 배치/메인 변경은 막습니다. 녹화 중지 상태 메시지를 받아도 실제 결과가 도착할 때까지 삭제·목록 교체 보호를 유지합니다. 이미 수신한 결과는 타일과 별개로 결과 창에 보관합니다.

홈페이지 모드의 base64 전송은 작은 조각으로 유지합니다. 서버는 디코딩한 바이트 배열을 계속 쌓는 대신 Blob 조각으로 보관하고, 최종 Blob 구성 후 조각 참조를 IndexedDB 저장 대기 전에 비웁니다. 전송 취소와 늦게 완료된 미사용 결과 삭제를 추가했으며 결과 삭제는 해당 결과를 만든 탭만 할 수 있습니다.

결과 창에서는 같은 형식의 전체 저장에 Worker를 만들지 않습니다. 구간 저장·다른 형식 저장에서만 Worker를 만들고, 입력을 해제한 뒤 출력 버퍼를 transfer합니다. 재생·재녹화 없이 구간을 저장하는 방식과 파일명은 유지합니다. 결과 탭 종료 시 IndexedDB 결과를 지우는 기존 서비스 워커 정리도 유지합니다.

## 검증

- 단위 검사: URL 명시 해제/만료/종료, Worker 성공/오류/취소/늦은 응답, 종료된 프레임의 추가 동작 방지와 원본 트랙 보존.
- 컨트롤러: 동시 캡처 제한, 종료 후 타이머·키 이벤트·표시 주기 0개, 결과 대기 중인 녹화 보호, 타일 제거 후 대기 상태 해제.
- 전송: 바이너리 보존, 부분 전송 취소·유휴 만료·초과 정리, 다른 탭의 결과 삭제 차단.
- 브라우저: 실제 Worker 스레드의 지연 생성·취소/종료·메시지 중단, 미리보기/다운로드 URL 0개, 갤러리 저장/실패/목록·자르기 보존과 상한.
- 실제 생성 영상: 720p 녹화의 영상·음성 보존과 원본 트랙 live, MP4/WebM 구간 복사와 재생 없이 저장, 결과 디코딩.
- 두 멀티뷰 모드의 기존 기능, 홈페이지 녹화 전송 전체 시나리오.

명령: `npm run typecheck`, `npm test`, `npm run test:media`, `npm run test:browser`.

홈페이지 전체 녹화 검사는 병렬 실행 중 데이터 대기 타임아웃이 있었고, 상태 진단을 추가한 단독 전체 실행에서 통과했습니다. 이를 제품 오류의 원인 확인이나 특정 성능 개선으로 해석하지 않습니다. 자동 검사의 HTTP·Chrome API는 모의 구현이며 실제 로그인·실방송은 사용자 Chrome에서 확인해야 합니다.

자원이 해제되는 경로와 한도는 검증했으나 전체 메모리 감소율이나 즉시 OS 메모리 반환을 보장하지 않습니다. 벤더 Mediabunny 코드·라이선스는 수정하지 않습니다.

## 직접 확인

1. S로 여러 장 촬영, 좌우 선택·자르기·복사·저장, 마지막 저장 후 창 닫힘.
2. R로 시작/중지, 결과 창에서 전체/구간 저장, 처리 취소 후 다시 저장, 처리 중 결과 창 닫기.
3. 녹화 종료 후에도 원래 방송의 재생·음성이 유지되는지 확인.
4. 녹화 중인 방송을 가리는 배치 변경이 안내와 함께 막히는지 확인.
5. 홈페이지 모드에서 녹화 중지 후 결과 창이 열리고 영상·음성이 정상인지 확인.
