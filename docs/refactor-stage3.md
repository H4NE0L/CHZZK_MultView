# 리팩토링 3단계 — 채팅 수집 분리

사용자 테스트를 마친 2단계(`9a90bcc`)를 기준으로 진행합니다. 버전은 2.0.3이며 main 반영은 별도입니다.

## 구조

```text
chat-collector.js — MutationObserver, 행 식별, 배치 전송과 수명 관리
  ├─ content/chat/dom-adapter.js — 선택자, 닉네임/본문/배지/원본 시각 읽기
  ├─ shared/chat/roles.ts — 역할 표식·본문 색상 판단과 우선순위
  ├─ shared/chat/history.ts — 해시·ID·시각을 보관하는 제한된 중복 이력
  └─ shared/important-chat.ts — payload 검증, 추가/제외·역할 필터, 100개 표시 모델
viewer/chat-renderer.ts — 검증된 메시지를 화면에 표시
```

ES 모듈 import는 빌드 시 콘텐츠 스크립트 안으로 묶습니다. manifest의 로딩 경로·프레임 메시지 형식·저장 키는 유지합니다. 역할 규칙과 이력은 strict TypeScript이며, DOM 어댑터와 조정기는 기존 동작을 보존하는 JS입니다. 전역 CZ* 연결은 테스트와 기존 실행 방식의 호환을 위해 남깁니다.

## 유지하는 동작

- API로 확인한 스트리머 이름과 일치하면 스트리머로 판별합니다.
- 역할 배지·의미 표식을 먼저 보고 본문 색상을 보조 기준으로 사용합니다. 닉네임 색은 사용하지 않습니다.
- 추가·제외 규칙과 역할 토글을 유지합니다. 제외가 우선하며 포함 규칙 변경으로 과거 기록을 지우지 않습니다.
- 원본 ID·관측한 행 교체·과거 스크롤 이력을 구분합니다. 같은 문장을 새로 보낸 실시간 메시지는 유지합니다.
- 이름 뒤 장식은 본문에서 제외하고 실제 이모티콘·텍스트는 보존합니다. 닉네임·본문을 읽을 때 원본 DOM을 변경하지 않습니다.
- 작성 시각은 검증된 원본 데이터/속성만 사용합니다. 없는 시각을 관측 시간으로 대체하지 않습니다. 실제 사이트에서 시각을 제공하지 않는 문제는 이번 단계에서 추가 수정하지 않습니다.

## 자원 수명

`stop()`은 관찰·배치/점검 타이머를 종료하며 필터 재설정에 필요한 이력은 유지합니다. `dispose()`는 최종 종료로, 그 이력과 행 참조용 캐시를 비우고 pagehide 리스너까지 해제합니다. 이후 configure는 다시 시작하지 않습니다. BFCache로 보존되는 화면은 최종 종료하지 않습니다.

중복 이력은 최대 2,048개이며 원문/DOM을 보관하지 않습니다. 수집 배치는 최대 100개, 화면 표시도 기존 100개 제한을 유지합니다. 수집 대상 여부는 새 메시지당 한 번 계산합니다.

## 검증

- 순수 역할/이력 검사: 한글·영문 표식, 우선순위, 본문 색, 정규화, 이력 상한·갱신·제외와 원문 미보관.
- 고정 DOM fixture 5개: 현재 CSS 모듈 구조, 관리자 배지 우선, 알 수 없는 행 발견, 닉네임 색 제외, 파트너 본문 색. 읽기 전후 원본 마크업이 같음을 확인.
- 기존 브라우저 검사: 역할·추가·제외·중복·과거 스크롤·배지·이모티콘·접기·기존 메뉴·원본 시각 처리.
- 수집기 30회 설정/끄기/종료 후 observer·타이머·pagehide listener 0개. 종료 후 configure로 되살아나지 않음.
- 주요 채팅 패널 30회 생성/종료 후 구독·감시자·추가 DOM 0개.

명령은 `npm run typecheck`, `npm test`, `npm run test:chat`, `npm run test:browser`입니다. 자동 검사는 모의 CHZZK DOM·응답을 사용하므로 실제 방송·다른 확장과의 동작은 Chrome에서 확인해야 합니다.

## 처리 비용 비교

`node scripts/profile-chat.cjs 9a90bcc`로 400개 메시지·DOM 최대 200행·대상 비율 10%를 3회 비교했습니다. 두 버전 모두 읽기 400회·수집 40개로 같습니다. 메인 스레드 작업 시간 중앙값은 기준 92.8ms, 변경 후 91.1ms이며 각각 91.4~99.1ms, 86.4~102.7ms 범위입니다. 이 작은 차이를 유의미한 성능 개선으로 해석하지 않습니다.

`node scripts/profile-chat-memory.cjs [기준 커밋]`은 2,400개 메시지 후 2,048개 이력 상한을 확인하고, GC 전후 이력만 비운 JS heap 차이를 측정합니다. 영상 디코딩·실방송·브라우저 전체 메모리는 포함하지 않습니다. 이번 단계는 구조 분리와 자원 해제를 검증했으며 전체 메모리 감소율을 보장하지 않습니다.

이번 단일 이력 측정은 기준 482,452B, 변경 후 486,304B로 비슷한 수준입니다. [측정 원자료](measurements/stage3-synthetic.json)에 CPU 3회 결과와 측정 범위를 기록합니다.

## 직접 테스트

두 실행 모드에서 스트리머·관리자·파트너와 직접 추가한 사용자의 수집, 제외 우선 적용, 이전 기록 유지, 위로 스크롤했다가 돌아와도 중복되지 않는지 확인합니다. 채팅 닫기/다시 열기·방송 전환·모아보기 접기/펼치기와 기존 치지직 메뉴도 확인합니다. 진단 collectorRevision은 `refactor-stage3-1`입니다.
