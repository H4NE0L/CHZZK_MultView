# 채팅 부하 점검 (2026-10-29)

## 확인한 처리와 수정

- 수집기가 알려진 채팅 행을 읽은 뒤 닉네임 기반 대체 탐색에서도 같은 행을 다시 읽었습니다. 알려진 행과 대체 탐색을 분리했습니다.
- 오래된 행이 삭제될 때 채팅 목록 전체를 다시 탐색했습니다. 목록에서 행만 제거된 변경은 건너뛰며, 개별 행의 본문·역할 변경은 계속 처리합니다.
- CSS 모듈 본문 대체 경로에서 같은 DOM Range를 두 번 복제했습니다. 복제한 내용을 재사용합니다.
- 부모가 같은 스트리머 이름을 반복 전송해 헤더를 다시 준비했습니다. 프레임별 이름이 바뀌거나 새 프레임이 준비될 때만 전송합니다.
- 영역 분리 이후 사용하지 않는 헤더 위치 보고용 전체 DOM MutationObserver가 남아 있었습니다. 보고 콜백이 없는 경우 감시를 시작하지 않습니다.
- 상세 점검 문구는 설정의 접힌 `수집 점검` 안으로 옮기고, 펼쳐서 볼 때만 갱신합니다. 점검 복사는 유지합니다.

## 재현 측정

`node scripts/profile-chat.cjs f2afbf3`

Chromium에서 가짜 채팅 400개를 10개씩 추가하며 DOM은 200개만 유지합니다. 10%를 수집 대상으로 지정하고 변경 전 커밋과 작업 코드를 각각 3회 실행했습니다. 수집기와 채팅 레이아웃만 포함하며 동영상·로그인·네트워크·다른 확장은 포함하지 않습니다.

| 지표 | 변경 전 | 변경 후 |
| --- | ---: | ---: |
| 행 해석 함수 호출 (매 실행 동일) | 8,800회 | 400회 |
| 전달된 대상 채팅 (매 실행 동일) | 40개 | 40개 |
| 메인 스레드 TaskDuration 중앙값 | 277.5ms | 64.9ms |
| 메시지 입력 완료 시간 중앙값 | 301.8ms | 161.8ms |

입력 완료 시간에는 타이머 대기도 포함합니다. TaskDuration은 CDP Performance 지표이며 위 모의 작업의 실행 구간에서만 측정했습니다. 전체 멀티뷰 CPU나 실제 방송 버퍼링이 같은 비율로 줄어든다는 의미는 아닙니다. 하드웨어·백그라운드 작업에 따라 재측정 수치는 달라집니다.

## 아직 실제 환경 측정이 필요한 부분

방송 타일은 각각 원본 방송 페이지와 동영상 디코딩·버퍼를 사용하므로 타일 수·화질이 CPU/GPU·메모리 사용량에 영향을 줍니다. 별도 원본 채팅 iframe과 타 확장 프로그램도 자원을 사용합니다. 이 항목들의 실제 비중은 로그인한 사용자 Chrome에서 확인해야 합니다.

Chrome 작업 관리자(Shift+Esc)에서 타일 수와 화질을 고정한 상태로 채팅 닫기 / 채팅 열기·모아보기 OFF / 모아보기 ON을 비교하면 원본 채팅과 수집 기능의 영향을 나눠 볼 수 있습니다. 모아보기 OFF도 원본 채팅은 유지하며, 채팅 닫기는 iframe과 수집을 중단합니다. 동일 조건에서 메모리가 계속 증가하는지는 별도 장시간 관찰이 필요하며 이번 검사는 메모리 누수를 입증하거나 배제하지 않습니다.
